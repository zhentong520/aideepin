## 一、系统定位

AiDeepin 是一个 **AI 应用底座平台**，把大模型能力封装成可直接使用的业务功能：智能体对话、知识库 RAG 问答、可视化工作流编排、绘图、MCP 工具接入、模型（LoRA）微调等。

形态为 **单后端 + 多前端**：后端是一个 Spring Boot 多模块单体应用，通过 Maven 分模块隔离「通用能力 / 用户端接口 / 管理端接口 / 启动装配」；前端按角色拆成面向普通用户的 user-web、面向运维的管理后台 admin-web，以及一个零构建的极简对话页 chat-ui。

本仓库是在上游 `langchain4j-aideepin` 基础上的**本地二开版本**，改动仅保留在本地磁盘，**不 commit、不 push 上游**。

### 4.2 知识库与 RAG（本轮重点治理）

#### 完整链路

```
文档来源 ──► 解析 ──► 清洗 ──► 分块 ──► 向量化 ──► pgvector
 │           │                                        │
 │           │                                        ▼
 │           │                                   候选召回（池 N 条）
 │           │                                        │
 │           │                              ┌─────────┴─────────┐
 │           │                          向量召回            关键词召回(BM25)
 │           │                              └─────────┬─────────┘
 │           │                                     RRF 融合
 │           │                                        │
 │           │                              重排 rerank（可选，本项目暂不可用）
 │           │                                        │
 │           └───────────────────────────────► 左右扩窗（可选）
 │                                                    │
 │                                            加出处抬头【文档名·第N段】
 │                                                    │
 │                                                    ▼
 │                                             注入 LLM Prompt
 └──► 上传 / URL 抓取 / API 拉取（031）
```

#### 入库（Ingest）

| 能力 | 说明 |
|---|---|
| 文档来源 | **上传文件**（`source_type=file`）／**URL 网页抓取**／**API 接口拉取**（031 新增，含 SSRF 防护，支持定时同步） |
| 支持格式 | **`txt` / `md` / `markdown` / `pdf` / Word(POI)**。此前 `.md` 不在白名单且被**静默丢弃**，2026-09-23 已修复为支持 + 白名单外**显式报错**（见 §8 硬规则） |
| 分块策略 | `DocumentSplitterFactory`：**`sentence_cn`（中文分句，默认）** / `recursive` / 自定义分隔符 / 父子分块 |
| 推荐参数 | **strategy=`sentence_cn`、size=512、overlap=0**（实测定型，详见下文） |
| 增强 | 分块自动提问（`adi_document_segment_question`）、父子 child chunk、命中计数 |
| 索引任务 | `adi_index_task` 记录异步索引状态，支持重试（`retryIndex`） |
| 失败可见 | 解析为空的文档明确标记 FAIL 并写明原因，杜绝"上传成功却永远搜不到" |
| 扫描件 OCR | `OcrService`：无文本层的扫描件 PDF 逐页渲染成 PNG 送外部 OCR；`POST /document/retryOcr/{uuid}` 就地补救，无需重传 |

#### 检索（Retrieve）

| 能力 | 说明 |
|---|---|
| 多路召回 | **EmbeddingRag**（向量）+ 可选**关键词/混合召回**（`retrieve_hybrid_enabled`，RRF 融合，`retrieve_rrf_k`） |
| **候选池大小** | `retrieve_max_results`：**0 = 按模型上下文窗口自适应**，上限 `RAG_RETRIEVE_NUMBER_MAX`（当前 10）。这是排序侧一切手段的**硬天花板** |
| 过滤阈值 | `retrieve_min_score`，注意**量纲是 `(1+cos)/2` 而非余弦**（见 §8） |
| 重排 | `retrieve_rerank_enabled`，**本项目暂无可用 rerank 服务商**（见 §8） |
| 左右扩窗 | `retrieve_neighbor_enabled` + `retrieve_neighbor_window`（默认**关闭**，推荐**1**）。补跨段上下文，**无需重建索引** |
| 出处抬头 | 每个片段输出带 `【文档名·第N段】`，提升 LLM 对多文档来源的辨识；邻段额外标注「（上下文）」 |

#### ⭐ 检索质量的实测结论（2026-09-22，`kb-eval` 评测器，n=73 中文金标）

1. **分块三件套**：`sentence_cn` / `512` / `overlap=0` 是最优解。
   `overlap` 在本项目中**完全空转**（0 / 64 / 160 切分结果逐块完全相同），且 `overlap > size` 会直接抛异常。
   想补跨块上下文请开「左右扩窗」，不要调 overlap。
2. **候选池大小才是天花板，不是排序函数**。
   答案排第 1 只占 **56.2%**；池=3 → 13.7% 的问题答案根本不在候选里；
   池=5 → 95.9%；**池=10 → 100%**（代价只是上下文 2658→5376 字符，零模型调用）。
   因此把 `RAG_RETRIEVE_NUMBER_MAX` 提到 10、新建库默认改 0（自动）。
3. **扩窗 ≠ 召回手段**。扩池修「候选太少」，扩窗修「答案跨段、不完整可读」。
   `w=1` 实测 recall@5 95.9%→97.3%、MRR 0.724→0.798；`w=2` 多付 ~21% 成本换 0 收益，**半径固定 1**。
4. **查询侧改写（Multi-Query / HyDE）已被实测否决**。
   `w1 + hyde-rrf` = 98.6% 仅比 `w1` 的 97.3% 多 1 题（n=73 噪声内），却要多花一轮 LLM。
   副产品结论值得记住：**多来源打分只比名次（RRF）或先校准，取 max 是错的**（同一批改写 max-cosine 90.4% → RRF 97.3%）。
5. **可答性不是瓶颈**：`answered@K` 与 `recall@K` 差异 ≤1 条，残余失败是纯排序问题。

#### Embedding 模型

当前 dev 环境配置为 **`qianwen:qwen3.7-text-embedding`（1024 维）**。

> ⚠️ **换 embedding = 换物理表**（后缀 `<platform>_<dimension>`），旧向量失效须重建索引。
> 早期曾用 `local:bge-small-zh-v1.5`(512) 与 `volcengine:doubao-embedding-vision`(2048)。
> **2048 维超过 pgvector 0.8.0 HNSW 索引的 2000 维上限**，检索会退化成顺序扫描（启动日志有 WARN），故已切回 1024 维。

#### ⭐ ClassifierNode 重构（已定案）

最终链路：**判据分离 → 关深度思考的裸调用 → 鲁棒解析 → 显式兜底分支**。

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 崩溃率（240 次真实调用） | 9.2%（随机） | **0** |
| 正确率 | 87.5% | **97.5% → 100%**（定案版） |
| 单次成本 | — | **0.001016 元（−49.4%）** |
| 结果摇摆 | 存在 | **0/60 归零** |

三条范式边界（重要）：

1. **判据只对「语义重叠的类别」写**，用时态/意图划分而非话题词枚举，每条带显式排除句。
   情感三分类这类互斥场景实测无收益只有 +29.8% 成本 → 已回滚。
2. **判据存在 `adi_workflow_node.node_config` jsonb 里 → 改判据是配置改动，不是代码改动。**
3. ⚠️ 代码层设不了 `temperature=0.0`：`buildChatLLM` 会把 `<=0` 静默改成 0.7，只能取 **0.01**。
   关闭深度思考请在方舟控制台设 `ThinkingType=disabled`（零代码）。

### 4.4 Agent 管理（二开）

- **工作设计**：JSON 结构化描述 Agent 的目标与执行步骤，渲染进 Character 的 `ai_system_message`
- **自动建角色**：创建 Agent 时自动生成关联 Character，`adi_agent.character_uuid` 保存映射，
  **对话仍走 `/chat/process`**，主链路零改动
- **工作流绑定**：一个 Agent 可绑多个工作流、可指定默认；绑定是**幂等 upsert + 部分唯一索引** `uk_adi_agent_workflow`
- **归属校验**：非本人资源返回「数据不存在」（不泄露资源是否存在）
- 接口：`/agent/list`、`/saveOrUpdate`、`/delete`、`/workflows`、`/bindWorkflows`

### 4.5 场景 Scene（二开）

- 场景绑定**多个 Agent**，对话页先选场景再选 Agent
- 幂等 upsert + 唯一索引 `uk_adi_scene_agent`，绑定时校验目标 Agent 归属当前用户
- 接口：`/scene/list`、`/saveOrUpdate`、`/delete`、`/agents`、`/bindAgents`

| 数据源管理 | 配置外部 PostgreSQL / MySQL 连接（`adi_db_datasource`），**列表接口不返回密码** |

| 能力 | 连接测试、列出表、列出字段、执行只读查询（默认 200 行，封顶 2000 行） |
| 同步知识库 | `adi_db_sync_task`：定时/手动执行 SQL → 结果按模板渲染 → 写入知识库 |
| 并发控制 | `Semaphore(8)` 闸门 + 30s 查询超时；同步任务 **CAS 抢占 running** 做幂等锁，>30min 判为僵死可重领 |

### 4.10 微调（LoRA Fine-tuning）

#### 链路

```
管理端建数据集 ──► 管理端建训练任务（FinetuneParamSpec 生成默认超参）
                        │
                        ▼
         training-worker 轮询 GET /ext/v1/finetune/job/claim
         （GPU 机，ext- key 鉴权）
                        │
      ┌─────────────────┼─────────────────┐
      │                 │                 │
  下载数据集        渲染 LLaMA-Factory    progress / log 回写
   (.jsonl)          YAML → 训练          （心跳合一）
      │                 │                 │
      └─────────────────┼─────────────────┘
                        ▼
              训练完成 → /job/{uuid}/complete
              上传 adapter zip + metrics(JSON)
                        │
                        ▼
        产物登记（adapter / merged / gguf）→ 可注册为 Ollama 平台模型
        AiModelInitializer 热加载 → 对话与知识库问答即可使用
```

#### 分工原则

> ⭐ **`FinetuneParamSpec`（服务端）是超参的唯一事实源。**
> 服务端在创建任务时已填好默认值并**派生好步数**（`logging_steps` / `save_steps` / `eval_steps`），
> Worker **只负责翻译成 YAML，不再自行决定默认值**——避免两边默认值打架。
> create 与 preview 必须共用同一个 `resolveHyperParams()`。

| 组件 | 职责 |
|---|---|
| `adi_finetune_dataset` / `adi_finetune_job` / `adi_finetune_artifact` | 数据集 / 任务 / 产物三张表（迁移 015，超参与指标在 022） |
| `AdminFinetuneController`（`/admin/finetune/**`） | 管理端 CRUD |
| `ExtFinetuneController`（`/ext/v1/finetune/**`） | Worker 协议接口，`ext-` key 鉴权 |
| `training-worker/worker.py` | 两种模式：`--mode mock`（无 GPU 跑通全链路）/ `--mode real`（真实训练） |

#### Worker 协议关键语义

- **`workerEpoch`**：claim 时返回，之后每次回传。任务被回收重派后，旧 Worker 的迟到写入会被拒绝（`accepted=false`），Worker 应立即退出
- **`stopRequested`**：进度回写响应带此标记，管理端请求停止时 Worker 应尽快中止并上报 `stopped`
- **熔断**：默认 5 分钟无进度回写会重置回 pending 重派；训练超过 24 小时强制失败
- **训练报告 `metrics`**：来自 `trainer_state.json` 的 `log_history`，含 `train_loss` / `eval_loss` / `best_step` / `total_steps` / `train_runtime` / `trainable_params` 等，落在 `adi_finetune_job.metrics`，管理端「训练报告」页签展示

## 六、关键设计约定（硬规则）

| 主题 | 约定 |
|---|---|
| **鉴权** | `Authorization: <token>` 直传裸 token，**不加 `Bearer `**；静态资源白名单由 `AdiConstant.WEB_RESOURCES` 控制（含 `.html`） |
| **SSE** | `/chat/process` 是 POST + SSE，前端必须 `fetch` + `body.getReader()` 按 `\n\n` 切块（**不能用 EventSource**） |
| **异步** | 工作流专用池 `workflowExecutor`（max 16 / queue 200 / AbortPolicy），池满返回 `A_WF_TOO_MANY_RUNNING`；**禁止 CallerRunsPolicy**（长任务会压死 Tomcat 线程） |
| **上下文** | 工作流在 `@Async` 线程执行，**ThreadLocal 不传递**，节点内必须从 `WfState.getUser()` 取用户 |
| **幂等** | 绑定关系一律幂等 upsert + 部分唯一索引；同步任务 CAS 抢占 running |
| **更新语义** | 所有更新接口 **patch 语义**：`null` = 未提交保留原值，空串 = 清空；密码空串 = 不改 |
| **越权** | 所有资源操作带 `userId` 归属校验，不匹配返回「数据不存在」而非「无权限」 |
| **MyBatis jsonb** | ⭐ **必须用 `resultMap` + `updateById`**。`resultType` 下 `@TableField(typeHandler)` 不生效（查出来恒 null），`lambdaUpdate().set(...)` 也不触发 typeHandler。历史 bug 已多次踩坑 |
| **KB 配置可见性** | ⭐ **任何可编辑的知识库配置字段都必须在 `KbInfoResp` 里能读回来**，否则管理端弹窗显示为「关闭」，运维保存一次就把运行中的配置项关掉 |
| **i18n 花括号** | ⭐ vue-i18n 文案里**不能直接写字面花括号**（`{{input}}` 或中文 `{参数名}`），**生产模式直接抛 SyntaxError**，开发模式只刷日志肉眼不可见。约定：文案写 ASCII 插值名 + 真实文本放 `braceLiteral.ts`。守卫脚本 `user-web/scripts/check-i18n-braces.mjs` 已挂 `npm run build` |
| **`min_score` 量纲** | ⭐ pgvector 的 `score = (1 + cos)/2`，默认 0.6 **等价于 cos ≥ 0.2**。拿原始余弦去比 0.6 会得出「答案全被滤掉」的**假结论** |
| **rerank 现状** | ⚠️ 本项目**暂无可用 rerank 服务商**：库内 `type='rerank'` 模型 0 行；唯一有 key 的火山方舟没有 Cohere 形状的 `/api/v3/rerank`（三条候选路径全 404）。能直连的是 SiliconFlow `BAAI/bge-reranker-v2-m3` / 本地 vLLM / Infinity / Xinference |
| **文档解析白名单** | `TEXT_DOC_TYPES = {txt, md, markdown}` + POI(pdf/word)。白名单外**显式报错**（`A0065`/`A0069`）而非静默丢弃。上传结果断言请以 `adi_document` 行数为准，不要信接口返回的 boolean |
| **本地模式** | 二开改动仅保留在本地磁盘，不 commit、不 push 上游 |
