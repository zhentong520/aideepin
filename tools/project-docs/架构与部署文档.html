1. 项目概述

AiDeepin 是一个 AI 应用底座平台，把大模型能力封装成可直接使用的业务功能：智能体对话、知识库 RAG 问答、可视化工作流编排、绘图、MCP 工具接入、模型微调等。形态是单后端 + 多前端：后端为 Spring Boot 多模块单体应用，通过 Maven 分模块隔离「通用能力 / 用户端接口 / 管理端接口 / 启动装配」。

本轮二开在此之上新增了 Agent（工作设计 + 工作流绑定）、场景（多 Agent 编排）、数据库 MCP（外部库只读查询并沉淀为知识库）、工作流 Database 节点，并补了一个免构建的 chat-ui 对话页，同时对异步线程池、接口幂等、更新一致性做了加固。

4.4 Agent 管理二开

  • 工作设计：JSON 结构化描述 Agent 的目标与执行步骤，渲染进 Character 的 ai_system_message
  • 自动建角色：创建 Agent 时自动生成关联 Character，adi_agent.character_uuid 保存映射，对话仍走 /chat/process，主链路零改动
  • 工作流绑定：一个 Agent 可绑多个工作流并指定默认；绑定为幂等 upsert + 部分唯一索引（uk_adi_agent_workflow）
  • 接口：/agent/list /saveOrUpdate /delete /workflows /bindWorkflows
  • 全部接口带归属校验，非本人资源返回「数据不存在」（不泄露资源是否存在）

4.5 场景（Scene）二开

  • 场景绑定多个 Agent，对话页先选场景再选 Agent
  • 绑定为幂等 upsert + 唯一索引 uk_adi_scene_agent
  • 绑定时校验目标 Agent 必须属于当前用户
  • 接口：/scene/list /saveOrUpdate /delete /agents /bindAgents

4.6 数据库 MCP二开

  • 数据源管理：配置外部 PostgreSQL / MySQL 连接，列表接口不返回密码
  • 只读保护：assertReadOnly 仅允许单条 select / with；拦截 ; 堆叠语句、select into（PG 建表）、into outfile（MySQL 写文件）、for update 等
  • 能力：连接测试、列出表、列出字段、执行只读查询（默认 200 行，封顶 2000 行）
  • 同步知识库：同步任务定时/手动执行 SQL → 结果按模板渲染 → 写入知识库
  • 并发控制：Semaphore(8) 闸门 + 30s 查询超时；同步任务用 CAS 抢占 running 做幂等锁，>30min 判为僵死可重领
  • 驱动：内置 postgresql、mysql-connector-j 8.0.33（sqlserver/oracle 离线缺驱动暂不支持）

6. 关键设计约定

主题约定
鉴权Authorization: <token> 直传裸 token，不加 Bearer ；静态资源白名单由 AdiConstant.WEB_RESOURCES 控制（含 .html）
SSE/chat/process 为 POST + SSE，前端必须用 fetch + body.getReader() 按 \n\n 切块解析
异步工作流专用池 workflowExecutor（max 16 / queue 200 / AbortPolicy），池满返回 A_WF_TOO_MANY_RUNNING；禁止 CallerRunsPolicy（长任务会压死 Tomcat 线程）
上下文工作流在 @Async 线程执行，ThreadLocal 不传递，节点内必须从 WfState.getUser() 取用户
幂等绑定关系一律幂等 upsert + 部分唯一索引；同步任务 CAS 抢占 running
更新语义所有更新接口 patch 语义：null = 未提交保留原值，空串 = 清空；密码空串 = 不改
越权所有资源操作带 userId 归属校验，不匹配返回「数据不存在」而非「无权限」
本地模式二开改动仅保留在本地磁盘，不 commit、不 push 上游

7.4 【二开】扫描件 OCR 接入

默认关闭。接入任意 OCR 服务（自建 PaddleOCR 服务 / 云 OCR 网关）后，扫描件与截图即可正常入库检索。

接口约定：POST <endpoint>，multipart 上传一张图片（字段名由 adi.ocr.file-field 指定，默认 file）， 返回 JSON，服务侧依次识别 text / data.text / result.text / results[].text（数组会拼接），非 JSON 时按纯文本处理。

adi:
  ocr:
    enabled: true
    endpoint: http://ocr.internal:8866/ocr   # 或 ADI_OCR_ENDPOINT 环境变量
    api-key: ${ADI_OCR_API_KEY:}             # 留空则不发鉴权头
    api-key-header: ${ADI_OCR_API_KEY_HEADER:}   # 留空用 Authorization: Bearer <key>
    file-field: file
    lang: ch
    dpi: 200            # 扫描件渲染清晰度
    max-pages: 20       # 单 PDF 最多识别页数，超出截断并告警
    max-file-mb: 40     # 超限直接放弃 OCR

行为与运维：

  • 解析为空的文档 → 自动走 OCR；成功则按普通文档入库索引，失败则标记 FAIL 并写明是 OCR 侧问题
  • 未启用 OCR 时，扫描件仍会标记 FAIL，原因写明"没有文本层，请先 OCR 处理"
  • 历史失败文档无需重传：POST /document/retryOcr/{uuid} 就地补识别并重索引；已有内容的文档会被拒绝，不会覆盖
  • OCR 同步执行在上传线程内（受 max-pages / max-file-mb 双重约束），大批量扫描件建议分批上传

7.5 上线检查清单

  • 修改默认管理员密码，ADI_ENCRYPT_AES_KEY 换成独立随机值
  • 数据库启用 vector 扩展；按 README 顺序执行初始化脚本
  • 各模型平台 API Key 在管理端配置（不写进 SQL / 代码）
  • Redis 设置密码并开启持久化
  • 确认 store_location（本地 / OSS），挂载好 /data/aideepin
  • 日志目录 /data/aideepin-logs 接入采集
  • Nginx 配置 HTTPS；SSE 接口需 proxy_buffering off（已配置）
  • 若前端独立域名部署，后端需补 allowedOriginPatterns("*")（当前 CORS 只允许同源）

7.5 容量与稳定性建议

  • 后端无状态，可水平扩容；注意 Redis 存 token、本地文件存储需改 OSS 才能多副本
  • 工作流是长任务且吃 LLM 并发，建议 chat 与 workflow 分离部署，或调大 workflowExecutor
  • pgvector 数据量到百万级后建议为向量列建 HNSW 索引并调参
  • 外部数据库查询有 Semaphore(8) 与 30s 超时保护，避免打满客户库
