## 一、项目概述

AiDeepin 是一个 **AI 应用底座平台**，把大模型能力封装成可直接使用的业务功能：智能体对话、知识库 RAG 问答、可视化工作流编排、绘图、MCP 工具接入、模型微调等。采用单后端 + 多前端的形态，后端是一个 Spring Boot 多模块单体应用，通过 Maven 分模块隔离「通用能力 / 用户端接口 / 管理端接口 / 启动装配」。

本轮二开在此之上新增了 **Agent（工作设计 + 工作流绑定）**、**场景（多 Agent 编排）**、**数据库 MCP（外部库只读查询并沉淀为知识库）**、**工作流 Database 节点**，并补了一个免构建的 **chat-ui 对话页**，同时对异步线程池、接口幂等、更新一致性做了加固。

### 代码规模

| 模块 | Java 文件数 | 职责 |
|---|---|---|
| `adi-common` | 645 | 全部业务能力：实体、Service、RAG、工作流、模型适配、文件、配置 |
| `adi-chat` | 36 | 用户端 REST 接口（35 个 Controller） |
| `adi-admin` | 14 | 管理端 REST 接口（14 个 Controller） |
| `adi-bootstrap` | 1 | 启动类与 `application*.yml` 装配 |

数据库 **51 张表 / 104 个索引 / 43 个触发器 / 397 条列注释**。

## 四、功能模块详解

### 4.1 对话与角色（Character）

| 能力 | 说明 |
|---|---|
| 角色管理 | 创建/配置 AI 角色：系统提示词、开场白、模型、温度、知识库绑定、MCP 绑定 |
| 流式对话 | `POST /chat/process`，**SSE 流式**返回；事件含 `[START]` `[THINKING]` `[META]` `[TOOL_CALL]` `[STATE_CHANGED]` `[AUDIO]` `[DONE]` `[ERROR]` |
| 上下文记忆 | 短期记忆（窗口内消息）+ 长期记忆（`memory/longterm`，向量化沉淀） |
| 消息存储 | `adi_character_message`，消息引用关联知识片段 / 图谱 / 记忆 |
| 预设角色 | `adi_character_preset`，中英两套展示数据 |
| 校验 | `characterUuid` 必须是合法 UUID v4，否则被 `AskReqValidator` 拒绝 |

### 4.2 知识库与 RAG

| 能力 | 说明 |
|---|---|
| 文档接入 | 上传文档 → 解析 → 分块 → 向量化 → 入库（`adi_document` / `adi_document_segment`） |
| 分块策略 | `DocumentSplitterFactory`：默认 / 自定义分隔符 / 父子分块（child chunk） |
| 检索 | **EmbeddingRag**（向量召回）+ **GraphRag**（图谱召回，Neo4j/AGE） |
| 融合 | **CompositeRag** 用 RRF（Reciprocal Rank Fusion）融合多路召回 |
| 重排 | `ContentReranker`：NoOp / Rerank 模型两实现 |
| 增强 | 分块自动提问（`adi_document_segment_question`）、段落扩展、命中计数 |
| 索引任务 | `adi_index_task` 记录异步索引状态，可重试 |
| 问答记录 | `adi_knowledge_base_qa_record` + 引用溯源 |
| 嵌入模型 | 可切换：本地 `bge-small-zh-v1.5`(512 维) / 火山方舟 `doubao-embedding-vision`(2048 维) |
| **【二开】扫描件 OCR** | `OcrService`：无文本层的扫描件 PDF 用 PDFBox 逐页渲染成 PNG 后送外部 OCR 服务，截图类图片直接送检；未启用时这类文档明确标记失败并给出原因，不再"上传成功却永远搜不到" |
| **【二开】失败补救** | 解析为空的文档在文档列表显示为 FAIL 并写明原因；启用 OCR 后可用 `POST /document/retryOcr/{uuid}` 就地补识别并重索引，无需重新上传 |

### 4.3 工作流引擎

| 能力 | 说明 |
|---|---|
| 可视化编排 | 节点 + 边（`adi_workflow_node` / `adi_workflow_edge`），画布拖拽 |
| 运行时 | `adi_workflow_runtime*` 记录每次执行，支持**断点续跑**（人工反馈后 resume） |
| 节点类型 | 18 种：Start / End / Agent / Answer / Classifier / **Database(二开)** / DocumentExtractor / FaqExtractor / Google / HttpRequest / HumanFeedback / KeywordExtractor / KnowledgeRetrieval / MailSender / OpenAiImage / Switcher / Template / TongyiWanx |
| 异步执行 | `WorkflowStarter` 走专用线程池 `workflowExecutor`，`@Async` 显式指定 bean |
| 上下文传递 | `ThreadContextTaskDecorator` 把当前用户带进异步线程并在 finally 清理 |
| 人工反馈 | HumanFeedback 节点挂起工作流，前端回填后 `resumeFlow` 继续 |

### 4.4 【二开】Agent 管理

- **工作设计**：JSON 结构化描述 Agent 的目标与执行步骤，渲染进 Character 的 `ai_system_message`
- **自动建角色**：创建 Agent 时自动生成关联 Character，`adi_agent.character_uuid` 保存映射，**对话仍走 `/chat/process`**，主链路零改动
- **工作流绑定**：一个 Agent 可绑多个工作流，可指定默认；绑定为**幂等 upsert + 部分唯一索引**（`uk_adi_agent_workflow`）
- 接口：`/agent/list` `/saveOrUpdate` `/delete` `/workflows` `/bindWorkflows`
- 全部接口带**归属校验**，非本人资源返回「数据不存在」（不泄露资源是否存在）

### 4.5 【二开】场景（Scene）

- 场景绑定**多个 Agent**，对话页先选场景再选 Agent
- 绑定为幂等 upsert + 唯一索引 `uk_adi_scene_agent`
- 绑定时校验目标 Agent 必须属于当前用户
- 接口：`/scene/list` `/saveOrUpdate` `/delete` `/agents` `/bindAgents`

### 4.6 【二开】数据库 MCP

- **数据源管理**：配置外部 PostgreSQL / MySQL 连接（`adi_db_datasource`），列表接口**不返回密码**
- **只读保护**：`assertReadOnly` 仅允许单条 `select` / `with`；拦截 `;` 堆叠语句、`select into`（PG 建表）、`into outfile`（MySQL 写文件）、`for update` 等
- **能力**：连接测试、列出表、列出字段、执行只读查询（默认 200 行，封顶 2000 行）
- **同步知识库**：`adi_db_sync_task` 定时/手动执行 SQL → 结果按模板渲染 → 写入知识库
- **并发控制**：`Semaphore(8)` 闸门 + 30s 查询超时；同步任务用 **CAS 抢占 running** 做幂等锁，>30min 判为僵死可重领
- 驱动：内置 postgresql、mysql-connector-j 8.0.33（sqlserver/oracle 离线缺驱动暂不支持）

### 4.7 模型与平台管理

| 能力 | 说明 |
|---|---|
| 平台 | `adi_model_platform`，支持 OpenAI / DeepSeek / DashScope / SiliconFlow / Ollama / **火山方舟 volcengine（二开新增）** / 任意 OpenAI 兼容平台 |
| 模型 | `adi_ai_model`，类型覆盖 text / embedding / image / asr / tts / vision / rerank |
| 适配层 | `languagemodel/` 下按厂商实现 `AbstractLLMService` 等抽象类：`OpenAiLLMService` `DeepSeekLLMService` `DashScopeLLMService` `SiliconflowLLMService` `OllamaLLMService` `OpenAiCompatibleLLMService` |
| 健康检查 | `ModelHealthService` 探测模型可用性 |
| 用量统计 | `adi_user_day_cost` 按天统计；`adi_llm_call_record` 记录调用明细 |

### 4.8 MCP 工具

- 平台侧 MCP 服务注册（`adi_mcp`）+ 用户侧启用配置（`adi_user_mcp`）
- 基于 `langchain4j-mcp`，支持 stdio / streamable-http
- 自定义参数类型处理器：`McpCustomizedParamDefinitionTypeHandler` `McpPresetParamTypeHandler` `UserMcpSettingTypeHandler`

### 4.9 绘图

- 文生图：OpenAI Image / 阿里通义万相 / 硅基流动
- 作品管理：绘图记录、点赞（`adi_draw_star`）、评论（`adi_draw_comment`）
- 工作流内节点：`OpenAiImageNode` `TongyiWanxNode`

### 4.10 技能（Skill）

- `adi_skill` 平台技能 + `adi_user_skill` 用户启用
- 对话时可挂载技能扩展能力

### 4.11 微调（Fine-tuning）

- 管理端创建数据集 / 训练任务（`adi_finetune_dataset` `adi_finetune_job` `adi_finetune_artifact`）
- 实际训练由独立 **training-worker**（Python + PyTorch + PEFT LoRA，r=8/alpha=16）执行，产出 LoRA 权重
- 接口：`/admin/finetune/**`、`/ext/finetune/**`

### 4.12 文件与存储

- `IFileOperator` 抽象，实现：`LocalFileOperator`（本地磁盘）、`AliyunOssFileOperator`（阿里云 OSS）
- `store_location` 配置切换（1=本地，2=OSS）

### 4.13 系统与权限

- 用户：注册/登录（邮箱验证码）、`adi_user.locale` 语言偏好
- **鉴权**：`TokenFilter`，`Authorization` 头整值即 token（**不剥离 `Bearer ` 前缀**），Redis 校验
- 角色权限：`adi_role`
- 系统配置：`adi_sys_config`，`Initializer` 启动时自动写入缺省项（如 `default_locale`）
- 统计：`StatisticService` / `TokenMonitorController` 观测用量
- 开放 API：`/ext/**`，由 `ExtApiAuthFilter` + 用户 API Key（`adi_user_ext_api_key`）鉴权

### 4.14 【二开】chat-ui 对话页

- 单文件 `chat.html`，原生 JS 零构建
- 场景 → Agent 两级下拉切换，SSE 流式渲染（`fetch` + `ReadableStream`，**不能用 EventSource**，因为需要自定义 Authorization 头）
- 管理面板三页签：建 Agent（含工作设计）／建场景绑 Agent／数据源管理
- 所有写操作按钮加防重复提交

## 六、关键设计约定

| 主题 | 约定 |
|---|---|
| 鉴权 | `Authorization: <token>` 直传裸 token，不加 `Bearer `；静态资源白名单由 `AdiConstant.WEB_RESOURCES` 控制（含 `.html`） |
| SSE | `/chat/process` 为 POST + SSE，前端必须用 `fetch` + `body.getReader()` 按 `\n\n` 切块解析 |
| 异步 | 工作流专用池 `workflowExecutor`（max 16 / queue 200 / AbortPolicy），池满返回 `A_WF_TOO_MANY_RUNNING`；**禁止 CallerRunsPolicy**（长任务会压死 Tomcat 线程） |
| 上下文 | 工作流在 `@Async` 线程执行，**ThreadLocal 不传递**，节点内必须从 `WfState.getUser()` 取用户 |
| 幂等 | 绑定关系一律幂等 upsert + 部分唯一索引；同步任务 CAS 抢占 running |
| 更新语义 | 所有更新接口 **patch 语义**：`null` = 未提交保留原值，空串 = 清空；密码空串 = 不改 |
| 越权 | 所有资源操作带 `userId` 归属校验，不匹配返回「数据不存在」而非「无权限」 |
| 迁移 | 见上一节硬规则 |
| 本地模式 | 二开改动仅保留在本地磁盘，不 commit、不 push 上游 |

### 7.4 【二开】扫描件 OCR 接入

默认关闭。接入任意 OCR 服务（自建 PaddleOCR 服务 / 云 OCR 网关）后，扫描件与截图即可正常入库检索。

**接口约定：** `POST <endpoint>`，multipart 上传一张图片（字段名由 `adi.ocr.file-field` 指定，默认 `file`），
返回 JSON，服务侧依次识别 `text` / `data.text` / `result.text` / `results[].text`（数组会拼接），非 JSON 时按纯文本处理。

```yaml
adi:
  ocr:
    enabled: true
    endpoint: http://ocr.internal:8866/ocr   # 或 ADI_OCR_ENDPOINT 环境变量
    api-key: ${ADI_OCR_API_KEY:}             # 留空则不发鉴权头
    api-key-header: ${ADI_OCR_API_KEY_HEADER:}   # 留空用 Authorization: Bearer <key>
    file-field: file
    lang: ch
    dpi: 200            # 扫描件渲染清晰度
    max-pages: 20       # 单 PDF 最多识别页数，超出截断并告警
    max-file-mb: 40     # 超限直接放弃 OCR
```

**行为与运维：**

- 解析为空的文档 → 自动走 OCR；成功则按普通文档入库索引，失败则标记 FAIL 并写明是 OCR 侧问题。
- 未启用 OCR 时，扫描件仍会标记 FAIL，原因写明"没有文本层，请先 OCR 处理"。
- 历史失败文档（启用 OCR 前上传的扫描件）无需重传：管理端点 `重试 OCR`（`POST /document/retryOcr/{uuid}`）就地补识别并重索引；已有内容的文档会被拒绝，不会覆盖。
- OCR 全程同步执行在上传线程里（单文件受 `max-pages` / `max-file-mb` 双重约束），大批量扫描件建议分批上传。

### 7.5 容量与稳定性建议

- 后端无状态，可水平扩容；注意 **Redis 存 token、本地文件存储需改 OSS 才能多副本**
- 工作流是长任务且吃 LLM 并发，建议 **chat 与 workflow 分离部署**，或调大 `workflowExecutor`
- pgvector 数据量到百万级后建议为向量列建 HNSW 索引并调参
- 外部数据库查询有 `Semaphore(8)` 与 30s 超时保护，避免打满客户库
