# AiDeepin 系统操作手册

> **写给完全没接触过本系统的人**：照着做一遍，你就能让一个「懂你们公司文档的 AI 助手」上线回答。
> 版本：2026-09-23 · 配套《架构设计说明.md》《部署说明.md》

---

## 序言：这东西到底是干什么的？

三句话说清：

1. 它是一个**搭 AI 助手的平台**——你不用写代码，在网页上点一点，就能做出一个会聊天、会查你们公司文档的机器人。
2. 它的核心能力是**知识库问答**：你把产品手册、规章制度丢进去，AI 就能照着这些文档回答，而不是瞎编。
3. 需要更花样的活儿（比如「先判断问题类型，再分派给不同的处理方式」），用**工作流**拖拽编排；需要 AI 自己挑工具干活的，用 **Agent**。

> 💡 **一句话路线图**
> 装模型 → 建知识库 → 传文档 → 建 Agent → 对话
> 走完这 5 步，一个能用的助手就出来了。本手册就按这个顺序写。

### 0.4.1 登录一直报「用户名或密码错误」？按顺序排查

**① 先确认你访问的是前端端口 `:1003`，不是后端 `:9999`**

登录接口在后端真实路径是 `/auth/login`（**没有 `/api` 前缀**）。浏览器开 `:1003` 时，Vite 代理会自动把 `/api/xxx` 改写掉前缀再转发给 9999，所以是正常的。

但如果你拿 `http://localhost:9999/api/auth/login` 直接调，会被 `TokenFilter` 拦掉，返回 **401 且响应体为空**——这**不是密码错**，是路径错。后端日志里会看到：

```
TokenFilter Unauthorized:/api/auth/login
```

**② 确认密码是不是被改过**

dev 库是长期使用的开发库，跑过的自动化测试可能重置过管理员密码。比对哈希前缀即可判断：

```bash
docker exec adi-dev-postgres psql -U aideepin -d aideepin -tAc \
  "select name||'  '||substr(password,1,25) from adi_user where is_admin;"
```

初始化脚本 `db_migration/all_dml.sql` 里的哈希是 `$2a$10$z44gncmQk6xCBCeDx55gMe...`。库里如果不是这一串，说明密码被改过（注意：bcrypt 每次加盐，**密码没变哈希也会变**，所以哈希不同不代表密码一定错，要实测）。

**③ 直接把密码重置成 123456**

```bash
# 1) 生成 jBCrypt 兼容的哈希（必须是 $2a$ 前缀，不能用 $2b$）
python -c "import bcrypt; print(bcrypt.hashpw(b'123456', bcrypt.gensalt(rounds=10, prefix=b'2a')).decode())"

# 2) 写回数据库（把下面 <HASH> 换成上一步的输出）
docker exec adi-dev-postgres psql -U aideepin -d aideepin -c \
  "UPDATE adi_user SET password='<HASH>', user_status=2, is_admin=true, is_deleted=false WHERE name='catkeeper';"

# 3) 清掉登录失败计数（否则会强制要求输入验证码）
docker exec adi-dev-redis redis-cli --scan --pattern "user:login:fail:*" | \
  xargs -r docker exec adi-dev-redis redis-cli del
```

**④ 关于验证码**：连续输错 **3 次**后，登录会强制要求填图形验证码。重置密码后记得顺手清掉第 3 步的 Redis 键，否则页面会一直弹验证码。

> `user_status` 取值：1=待验证 / **2=正常** / 3=冻结。登录被拒时要一并确认是 2。

## 第 2 章：五个新手任务（手把手）

### ⭐ 任务 1：让 AI 能说话（配置模型）

> **不做这一步，系统里什么都跑不起来。** AI 对话本质上是调用第三方厂商的 API。

#### 第 1 步：挑一个模型厂商并拿到 API Key

推荐新手用**火山方舟（ARK）**或**阿里云 DashScope（百炼）**，国内直连、速度稳。
去对应平台注册 → 开通大模型服务 → 创建一个 **API Key**，复制下来。

#### 第 2 步：在管理后台配置平台

1. 进 `http://localhost:1003` → **平台配置**
2. 找到你要的厂商（如 `volcengine` / `dashscope`），点编辑
3. 填两个字段：
   - **Base URL**：厂商给的接入地址（如方舟的 `https://ark.cn-beijing.volces.com/api/v3`）
   - **API Key**：刚才复制的 Key
4. 如果它是「OpenAI 兼容」型厂商，把 **`is_openai_api_compatible` 勾上**（方舟、千问 MaaS 都要勾）
5. 保存

> 💡 **什么是「OpenAI 兼容」**：这个厂商的接口格式抄了 OpenAI，勾上之后系统就用通用的方式去调它。
> 不确定就先勾上，调不通再取消试试。

#### 第 3 步：确认模型已启用

1. 左侧 **模型管理**
2. 找到你要用的对话模型（text 类型），确认它启用、且所属平台是刚才配好的那个
3. 顺便记下它的**名称**，下一步选模型要用

#### 第 4 步：立刻验证

打开 `http://localhost:9999/chat.html`，随便问一句「你好」。
能正常流式出字 → 成功 🎉

**如果失败**：翻到第 4 章「ai 不回答 / 报错」那一节。

### ⭐ 任务 2：建第一个知识库

> 知识库 = 你喂给 AI 的资料堆。没有知识库，AI 只会用它的通用知识（容易瞎编）。

1. 打开用户端 `http://localhost:1002`，登录（没有账号就注册）
2. 左侧或直接访问 **知识库**
3. 点 **新建知识库**
4. 填写：

| 字段 | 怎么填 | 建议 |
|---|---|---|
| 名称 | 起个好认的名字，如「产品手册」 | — |
| 简介 | 一句话说明 | — |
| **严格模式** | 这个选项很重要，看下面👇 | **新手选「宽松」** |
| 其他参数 | **全部先别动**，用默认值 | — |

> ⚖️ **严格模式 vs 宽松模式**
> - **严格模式**：知识库里搜不到就直接说「不知道」。**优点**：绝不瞎编。**缺点**：问边界问题会频繁答不上来。
> - **宽松模式**：搜不到就丢给大模型用通用知识回答。**优点**：什么问题都有回应。**缺点**：可能编造。
>
> 做**制度/客服**类建议严格；做**通用助手**建议宽松。新手先用宽松，跑通了再切严格测试效果。

5. 保存后进入知识库详情页

---

### ⭐ 任务 3：把文档喂进去

#### 方式 A：上传文件（最常用）

在知识库详情页 → **上传文档** → 选择文件。

| 支持 | 不支持 |
|---|---|
| `.txt` `.md` `.markdown` `.pdf` `.doc` `.docx` | 扫描的图片 PDF（**需要先开 OCR**）、Excel、PPT、zip |

> 🔴 **最容易踩的坑：传上去了却永远搜不到**
> 老版本曾经「上传成功但静默丢弃」，现在已改成**显式报错**。
> 一旦你看到文件出现在列表里但状态是 **FAIL**，点开看失败原因：
> - 提示「没有文本层」→ 这是扫描件，需要开 OCR（见第 3.5 节）
> - 提示不支持的类型 → 先把内容复制成 `.md` 或 `.txt` 再传

#### 方式 B：抓取网页（帮助中心 / Wiki 用这个）

适合知识本来就挂在网上、而且会持续更新的情况。

1. 知识库详情页找「文档来源 / 添加 URL」入口
2. 填写：

| 字段 | 说明 |
|---|---|
| 来源类型 | 选 `url`（抓整个网页正文）或 `api`（拉接口返回的 JSON） |
| 抓取地址 | 网页 URL / 接口地址（只支持 http、https） |
| 请求方法 | api 来源用 GET 或 POST |
| 取值路径 | api 返回 JSON 时，要取哪一段作正文，如 `data.list.content`；空 = 整段响应 |
| 自动同步周期 | 填分钟数（如 `1440` = 每天）；**填 0 = 只手动同步** |

3. 保存后点「立即同步」试一次

> ⚠️ **安全限制**：填写的地址会被系统校验，内网地址、本机、云元数据地址会被拒绝（防 SSRF 攻击）。
> 这是故意的，别想办法绕过——要抓内网请先把源站暴露成正常域名。

#### 方式 C：从数据库导入

如果你要问的数据在**业务数据库**里：用户端 **数据源** → 配置只读连接 → 写 SQL 查询 → 定时把结果渲染成文档进知识库。详见 §3.6。

#### 传完等待索引

文档上传后需要**异步切块+向量化**。看 Po 状态从「处理中」变成「成功」。
文档多的话要等一会儿——这段时间别重复点，也别批量一次性丢几百个文件。

> 💡 **判断有没有真的存进去**：不要只看上传接口返回「成功」。
> 最可靠的办法是看文档列表里**有没有这一行、状态是什么**。

### ⭐ 任务 4：建一个 Agent（真正的助手）

> **角色（Character）**= 一个会说某类话的 AI 人格。
> **Agent** = 在角色之上，再加「工作设计」（目标+步骤）和「工作流绑定」。

#### 为什么推荐用 Agent

创建 Agent 时会**自动生成配套的角色**，对话还走原来的接口，**不需要改任何已有流程**。

#### 操作步骤

1. 用户端 → 进入对话页，左侧或菜单里找 **新建 Agent**
2. 填写：

| 字段 | 怎么填 | 说明 |
|---|---|---|
| 名称 | 「财务小助手」这类 | — |
| 简介 | 一句话 | — |
| **选择模型** | 选刚才配好的对话模型 | 决定聪明程度和成本 |
| **温度** | **新手填 0.3~0.7** | 越低越稳定严谨，越高越发散有创意。制度类问答建议 0.3 |
| **系统提示词 / 工作设计** | 告诉它「你是谁、干什么、怎么回答」 | 见下方模板 |
| **绑定知识库** | 勾选任务 2 建好的库 | 这是「它懂你们文档」的关键 |
| **绑定工作流** | 暂时跳过 | 任务 5 再说 |

#### 系统提示词模板（直接改着用）

```
你是{公司名}的{岗位}助手，负责解答员工关于{业务领域}的问题。

回答规则：
1. 只依据知识库中的内容回答；找不到就明确说「这个问题我暂时无法回答，请联系{负责人}」。
2. 回答要简洁，能用步骤说明就用步骤。
3. 涉及金额、日期等关键数字时，必须核对后再给出。
4. 不允许编造知识库里没有的内容。

语气：专业、友好、不说套话。
```

3. 保存
4. 回到对话页，选中这个 Agent，开始问

#### 🎯 立刻做一次「可用性测试」

问三类问题：

| 类型 | 例子 | 期望表现 |
|---|---|---|
| **查得到** | 问文档里明确写了的内容 | 答得准、并给出处 |
| **查不到** | 问完全无关的内容 | 严格模式：说不知道；宽松模式：通用回答 |
| **边界模糊** | 用口语/错别字问同一件事 | 还能答上来（考验向量检索） |

如果第 1 类答不准，不是 AI 笨，**多半是检索没取到**——去第 3 章调参数。

### ⭐ 任务 5：搭第一条工作流

> 什么时候该用工作流？当你的需求是**固定的多步流程**，而不是自由对话。
> 例：「用户提问题 → 判断是退款还是咨询 → 退款的走退款流程，咨询的查知识库回答」。

#### 操作步骤

1. 用户端 → **工作流** → 新建
2. 你会看到一张画布，左侧是**节点列表**
3. **每个工作流必须有且只有一个「开始」节点**
4. 从左侧拖节点到画布，用鼠标**从节点的圆点拉线连线**
5. 点节点右侧会弹出**属性面板**，配置这个节点干什么
6. 右上角保存 → 试运行

#### 最常用节点速查

| 节点 | 什么时候用 | 配置要点 |
|---|---|---|
| **开始** | 必须有 | 定义入参（如用户输入的变量名） |
| **结束** | 标记出口 | — |
| **生成回答** | 让 LLM 直接输出一段文字 | 写提示词，注意用 `{变量名}` 引用上游结果 |
| **知识检索** | 查知识库 | 选知识库、设召回条数 |
| **内容归类** | 判断输入属于哪一类，再分流 | 写**互斥**的类别判据，见下方 ⚠️ |
| **条件分支** | 按变量值路由 | 纯逻辑判断，不调模型，**省钱快** |
| **Agent** | 想让模型**自己决定**调哪个工具 | — |
| **MCP 工具** | **确定性地调某一个** MCP 工具 | 选工具 + 写死参数 |
| **技能** | 读取技能指令 / 执行技能脚本 | — |
| **数据库查询** | 查外部业务库（只读取multipart select） | 先去「数据源」配连接 |
| **Http 请求** | 调外部接口 | 填 URL / Body |
| **人机交互** | 需要人工确认才能继续 | 工作流会挂起，回填后继续 |
| **模板转换** | 数据格式转换 | — |
| **邮件发送** | 发邮件通知 | 需配邮件服务 |

> ⚠️ **「内容归类」节点写判据的两条铁律**
> 1. **只给语义重叠的类别写判据**。比如「退款政策 vs 计费政策」这种容易混的需要写；
>    「好评 vs 差评」这种天然互斥的**不用写**，写了白花成本。
> 2. **用时态/意图划分，别用话题词枚举**。每条判据带一句显式排除句。
>    例如：「已发生的扣款问题 → 归为计费问题；用户询问价格规则（尚未发生扣款）→ 归为定价问题，**不属于计费**」。
>
> 💡 判据存在数据库里，**调判据是改配置不是改代码**，随时可以微调再测。

#### 🆚 Agent 节点 vs MCP 节点（新手最常搞混）

|  | Agent 节点 | MCP 节点 |
|---|---|---|
| 谁来选工具 | **大模型自己决定** | **你在节点里写死** |
| 适合 | 开放任务、需要灵活应变 | 确定性的一步操作 |
| 成本 | 高（要额外一轮推理） | 低 |

需要确定性的时候用 MCP，需要灵活性的时候用 Agent。

## 第 3 章：让知识库答得更准（调参指南）

> 这一章是**知识库问答不准**时的解决思路。默认参数已经调好了，先别急着改。

### 3.1 当前推荐参数（实测定型，别乱改）

| 参数 | 推荐值 | 为什么 |
|---|---|---|
| 分块策略 | **`sentence_cn`**（中文分句） | 实测中文场景 512 下 intact 100%、recall@10 100%，全面不劣于其他策略 |
| 分块大小 | **512** | 512 是拐点；256 反而变差（金标片段可能比块还长），1000 会主题稀释 |
| 重叠 overlap | **0** | ⚠️ **本项目中完全空转**：填 0 / 64 / 160 切出来**逐块完全相同**；而且 `overlap > size` 会直接报错 |
| 左右扩窗 | **开启，半径 1** | 解决「答案跨两个段落」的问题，recall@5 95.9%→97.3% |
| 召回条数（池） | **0（自动）** | 池大小是排序效果的**硬天花板**，见下 |

### 3.2 ⭐ 最重要的一条：先看「池」够不够大

很多人答不准就去换更强的重排模型，**这是花错钱**。真相是：

> **重排只能在已经取回来的候选里排序。答案压根没被取回来，再牛的模型也救不了。**

实测 73 道题：答案排第 1 的**只占 56%**。

| 召回池大小 | 答案在池内的比例 | 平均上下文长度 |
|---|---|---|
| 3 条 | 86.3%（13.7% 注定答不对） | 1651 字符 |
| 5 条 | 95.9% | 2658 字符 |
| **10 条** | **100%** | 5376 字符 |

**做法**：进知识库设置 → 找「召回条数 / retrieve_max_results」→ 设为 **0（按模型上下文自动）**。
系统上限已调到 10。代价只是上下文从 2658 涨到 5376 字符，**不多花一次模型调用**。

### 3.3 开启左右扩窗（解决「答案被切断」）

文档里一个完整的规则被切成两段，取回来只有一半 → AI 答不完整。

**做法**：知识库设置里开启 `retrieve_neighbor_enabled`，窗口填 **1**。

| 为什么是 1 | 数据 |
|---|---|
| 窗口=1 | recall@5 95.9%→97.3%，MRR 0.724→0.798，上下文 ×1.97 |
| 窗口=2 | 多付 ~21% 成本，**收益为 0** |

✅ **开扩窗不需要重建索引**，对已有文档的下一次检索即时生效。

### 3.4 不要做的事

| ❌ 别做 | 原因 |
|---|---|
| 调 overlap | 实测完全无效，见 3.1 |
| 急于接 rerank（重排）模型 | 本项目**当前没有可用的 rerank 服务商**——火山方舟没有 Cohere 形状的 rerank 接口。想用得接 SiliconFlow 的 `BAAI/bge-reranker-v2-m3` 或自建 vLLM |
| 加「查询改写（Multi-Query / HyDE）」 | 实测否决：加上只比单开扩窗多答对 1 道题（噪声范围内），却每问多花一轮 LLM |
| 随便换 embedding 模型 | ⚠️ **换 embedding = 换数据库里的向量表，所有文档必须重新向量化**。上线前就要定死 |

### 3.5 用内存保护陷阱：`min_score` 的坑

知识库里有个「最低相似度分数」，默认 0.6。

⚠️ **这个 0.6 不是余弦相似度！** 系统的算法是 `score = (1 + cos) / 2`，
所以 **0.6 其实等价于余弦 ≥ 0.2**（相当宽松）。

> 曾经有人拿原始余弦去比 0.6，得出「答案全被过滤掉了」的错误结论。
> 别动这个值，除非你真的懂它的量纲。

### 3.6 扫描件 PDF 怎么办

这类 PDF 本质是图片，没有文字层，系统会标记为 **FAIL**，原因写「没有文本层」。

两个解法：

| 解法 | 做法 |
|---|---|
| **自己先用 OCR 工具转成 txt** | 零配置，推荐小批量 |
| **接一个 OCR 服务**（运维做） | 配好后在文档列表点「重试 OCR」就地补救，**历史失败文档不用重新上传** |

> 📌 OCR 默认关闭。有大批量扫描件才值得接，OCR 是同步执行的（受页数/体积上限约束），
> 建议分批上传而不是一次丢几百个大 PDF。

## 第 4 章：出问题了怎么办

> 按现象找，不要慌。绝大多数问题都在下表里。

### 4.1 AI 不回答 / 报错

| 现象 | 排查顺序 |
|---|---|
| 完全没反应 | ①后端还活着吗？开 `http://localhost:9999/swagger-ui.html` 试试 ②端口 9999 被占了？`netstat -ano | grep :9999` |
| 返回 401 | Token 传错了。本项目要**裸传 token，不能加 `Bearer ` 前缀**；也可能是登录过期了，重新登录 |
| 返回「模型不可用」 | ①模型管理里这个模型启用了吗 ②平台配置的 API Key 对不对 ③账户余额还有吗 |
| 返回 403 / 找不到供应商 | Base URL 填错了（方舟/千问这类要确认路径） |
| 流式输出卡住不动 | Nginx 要配 `proxy_buffering off`；前端要用 `fetch` 读流，不能用 `EventSource` |

### 4.2 上传文档相关

| 现象 | 原因 / 解决 |
|---|---|
| 上传报「不支持的类型」 | 只支持 `txt/md/markdown/pdf/word`。转成 txt 或 md 再传 |
| 列表里状态是 FAIL | 点开看**失败原因**：多为扫描件无文本层（见 §3.6） |
| 上传后搜不到 | ① 看文档状态是不是「成功」② 看向量表有没有数据 ③ 把 `min_score` 调低试试（注意它不是余弦，见 §3.5） |
| 上传 .md 完全没反应 | 老版本的 bug（静默丢弃），现已修复为支持 + 显式报错 |
| 批量上传时整个系统变卡 | 数据库连接池不够。让运维设 `ADI_DB_POOL_SIZE=32` |
| 上传大文件失败 | 单文件上限 600MB |

### 4.3 知识库答不准

按这个顺序自查（**顺序很重要，别跳**）：

1. **先看池够不够大** → 召回条数设为 0（自动），见 §3.2
2. **再开左右扩窗**（半径 1）→ 见 §3.3
3. **确认严格/宽松模式**符合预期 → 见任务 2
4. **确认文档真的索引成功了** → 看文档列表状态
5. **手动测一次**：在知识库详情页直接问，看它召回了哪些片段（有出处抬头）
6. **检查系统提示词**是不是限制得太死

> ⚠️ 答不准**不是先换更聪明的模型**。先确认「答案有没有被取回来」——
> 这条比换模型重要得多。

### 4.4 工作流相关

| 现象 | 原因 / 解决 |
|---|---|
| 报 `unsupported workflow component` | 这个节点没在 `adi_workflow_component` 表里注册。让运维执行对应迁移脚本 |
| 拖出来的节点保存后又多了几个 | 老 bug（已修）：更新时没继承节点 id，每次保存插入重复节点 |
| 运行详情里某个节点的指标不显示 | 前端「六处注册」漏了第六处（`RuntimeNodes.vue` 的指标 chip） |
| 提示流程太忙 | 工作流线程池满了（`A_WF_TOO_MANY_RUNNING`）。等一下或让运维调大线程池 |
| 节点里拿不到当前用户 | ⚠️ 工作流跑在异步线程，**ThreadLocal 不传递**。节点里要从 `WfState` 取 |
| 用人机交互节点后流程不动了 | 这是正常的——它在等人工回填。输入内容后点继续 |

### 4.5 后台/界面异常

| 现象 | 原因 / 解决 |
|---|---|
| 某个面板白屏 / 不渲染 | i18n 文案里写了字面花括号（生产模式会抛 SyntaxError）。跑 `user-web/scripts/check-i18n-braces.mjs` |
| 改了知识库配置，重启后又变回关闭 | 该字段没在返回结构里被读回，页面显示为「关闭」，保存时把它覆盖了。这是已知陷阱类 bug |
| 容器重启后 502 | Nginx 硬编码了容器 IP。确认用了变量式 `proxy_pass` + `resolver` |
| 前端能开但所有接口 401 | 见 §4.1 |

### 4.6 微调任务相关

| 现象 | 原因 / 解决 |
|---|---|
| 任务一直卡在 pending | **没有 Worker 在线领取**。检查 GPU 机上 Worker 是否活着、Key 对不对（`ext-` 开头）、能否访问后端 |
| 训练到一半任务被重置 | 心跳超时（5 分钟没上报进度）自动回收重派。看 Worker 日志 |
| 训练超过 24 小时被强制失败 | 熔断机制。拆分数据集或调整参数 |
| 不知道超参怎么填 | **不用填**——系统会根据你选的基座自动给默认值并算好步数。详情页有「训练指南」 |

### 4.7 实在解决不了

收集这四样再找人帮忙，**没有这四样别人也只能猜**：

1. **在哪个页面、点了什么**（最好截图）
2. **完整报错原文**（不要只说「报错了」）
3. **时间点**（方便查日志）
4. **后端日志**：`E:/reg-project/data/logs/adi-backend.log`（生产在 `/data/aideepin-logs`）

## 附录 A：名词对照表

| 名词 | 白话解释 |
|---|---|
| **Agent（智能体）** | 一个带目标和工作步骤的 AI 助手；创建时会自动生成配套角色 |
| **角色（Character）** | AI 的"人格设定"，包含系统提示词、用哪个模型、绑哪些知识库 |
| **知识库（KB）** | 你喂给 AI 的一堆文档，它会从这里找答案 |
| **RAG** | 「先检索文档，再让 AI 照着答」的技术，防止 AI 瞎编 |
| **分块（Chunk）** | 把长文档切成小段，方便检索和放进模型上下文 |
| **向量 / Embedding** | 把文字变成一串数字，语义相近的文字数字也相近，这样就能「按意思搜索」 |
| **pgvector** | PostgreSQL 的向量检索插件，本项目的搜索引擎 |
| **候选池 / 召回条数** | 一次检索先取回多少条候选。这是回答准不准的地基 |
| **左右扩窗** | 命中某段时顺带把前后段落也带上，避免答案被切一半 |
| **严格/宽松模式** | 搜不到时直接说不知道 / 交给大模型自由发挥 |
| **工作流（Workflow）** | 拖拽式编排的固定多步流程 |
| **节点（Node）** | 工作流里的一个步骤（查知识库、调接口、发邮件…） |
| **MCP** | 让 AI 调用外部工具的标准协议。MCP 节点 = 确定性地调一个工具 |
| **技能（Skill）** | 一段可复用的指令/脚本包，挂载后 AI 会用 |
| **数据源** | 你配置的外部数据库连接（只读） |
| **Token** | 模型计费单位，大致可以理解为「字数」。中文一个字通常占 1~2 个 token |
| **微调 / LoRA** | 用你自己的数据在基座模型上再训练，让它更懂你的业务。需要 GPU |
| **worker**（training-worker） | 跑在 GPU 机上、真正执行训练的进程 |
| **SSE** | 服务端流式推送，就是 AI 回答一个字一个字往外蹦的技术 |
