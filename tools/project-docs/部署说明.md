## 零、先搞清楚要部署什么

系统由 **5 类进程**组成，按依赖顺序启动：

| # | 组件 | 必需 | 默认端口 | 说明 |
|---|---|---|---|---|
| 1 | PostgreSQL 16 (pgvector + AGE) | ✅ | 5432 | 业务主库 + 向量库 |
| 2 | Redis 6.2.5 | ✅ | 6379 | Token、缓存、工作流状态 |
| 3 | `adi-bootstrap` 后端 | ✅ | 9999 | 唯一后端，Spring Boot |
| 4 | `user-web` / `admin-web` 前端 | ⭕ | 1002 / 1003 | 生产环境由 Nginx 托管静态包 |
| 5 | `training-worker` | ⭕ | — | **只在做 LoRA 微调时才需要**，跑在 GPU 机上 |

> `chat-ui` 不是独立进程——它由后端静态托管，后端起来了就有。

三种部署形态对照：

| 形态 | 适用场景 | 数据怎么起 | 备注 |
|---|---|---|---|
| **本地开发** | 单人开发调试 | `E:/reg-project/dev-env` 的 Docker Compose | 本文档第 2 节 |
| **Docker 全栈** | 单机演示 / 小型生产 | `aideepin/docker/docker-compose.yml` | 本文档第 6 节 |
| **分离部署** | 正式生产 | 外部 PG + Redis + 后端 jar + Nginx | 推荐，便于各自扩容 |

## 二、本地开发环境（推荐新手从这里开始）

### 2.1 用脚本一键启动

`dev-scripts/` 下已有 5 个脚本，**按顺序双击即可**：

| 顺序 | 脚本 | 作用 |
|---|---|---|
| 0 | `build-backend.bat` | 编译后端（跳过测试、离线模式），日志写 `mvn-build.log` |
| 1 | `start-backend.bat` | 启动后端 `:9999` |
| 2 | `start-user-web.bat` | 启动用户端 `:1002` |
| 3 | `start-admin-web.bat` | 启动管理端 `:1003` |
| — | `stop-all.bat` | 一键杀掉 9999 / 1002 / 1003 |

> 🔴 **端口被顶掉的坑（2026-09-24 实测）**
> 本机环境变量里若存在 **`SERVER__PORT`**（双下划线，例如 `SERVER__PORT=55805`），
> Spring Boot 的 relaxed binding 会把它解析成 `server.port`，**把配置里的 9999 顶掉**。
> 结果是后端去监听一个莫名其妙的端口，而那个端口通常已被编辑器/其他服务占用，
> 启动直接失败并报 `Web server failed to start. Port 55805 was already in use.`
>
> 排查：`env | grep -i SERVER`
> 解决（二选一）：
> ```bash
> unset SERVER__PORT                       # 清掉污染源
> java -jar ... --server.port=9999         # 或命令行显式指定（优先级最高）
> ```

> ⚠️ **为什么脚本不用 `mvn` 命令**：Git Bash 下 `mvn` 启动脚本会因 classpath 分隔符报
> `Error: Could not find or load main class`；PowerShell 直接传 `-D` 参数又会把路径里的点号改写。
> 脚本里绕过的方式是直接用 `java` 调 plexus launcher：

```bat
"%JAVA_HOME%\bin\java.exe" ^
  -classpath "%MAVEN_HOME%\boot\plexus-classworlds-2.8.0.jar" ^
  "-Dclassworlds.conf=%MAVEN_HOME%\bin\m2.conf" ^
  "-Dmaven.home=%MAVEN_HOME%" ^
  "-Dmaven.multiModuleProjectDirectory=%PROJECT_DIR%" ^
  org.codehaus.plexus.classworlds.launcher.Launcher ^
  -DskipTests -o compile
```

等价命令行（打包用）：

```bash
java -classpath "E:/tools/apache-maven-3.9.9/boot/plexus-classworlds-2.8.0.jar" \
  "-Dclassworlds.conf=E:/tools/apache-maven-3.9.9/bin/m2.conf" \
  "-Dmaven.home=E:/tools/apache-maven-3.9.9" \
  "-Dmaven.multiModuleProjectDirectory=E:/reg-project/aideepin/server" \
  org.codehaus.plexus.classworlds.launcher.Launcher \
  -DskipTests -o package
```

## 三、数据库初始化（全新安装，必做）

> ⚠️ **这一步的顺序不能错，漏第 1 步后面全会失败。**

### 3.1 启用扩展

```bash
docker exec adi-dev-postgres psql -U aideepin -d aideepin -c "CREATE EXTENSION IF NOT EXISTS vector;"
docker exec adi-dev-postgres psql -U aideepin -d aideepin -c "CREATE EXTENSION IF NOT EXISTS age;"
```

> `vector` 是 pgvector；`age` 是图数据库（GraphRAG 用，可选但建议装上）。
> 这两条在 `all_ddl.sql` 里**刻意注释掉了**（需要超级用户权限），必须手工执行。

### 3.2 执行初始化脚本（严格按此顺序）

```bash
MIG=E:/reg-project/aideepin/server/db_migration

psql -v ON_ERROR_STOP=1 -f $MIG/all_ddl.sql        # 结构：51 张表 + 索引 + 触发器 + 注释
psql -v ON_ERROR_STOP=1 -f $MIG/all_dml.sql        # 主数据：管理员 / 系统配置 / 平台 / 模型
psql -v ON_ERROR_STOP=1 -f $MIG/all_dml_cn.sql     # 中文展示数据（英文包则用 all_dml_en.sql）
```

在 Docker 容器里执行：

```bash
docker exec -i adi-dev-postgres psql -v ON_ERROR_STOP=1 -U aideepin -d aideepin < $MIG/all_ddl.sql
docker exec -i adi-dev-postgres psql -v ON_ERROR_STOP=1 -U aideepin -d aideepin < $MIG/all_dml.sql
docker exec -i adi-dev-postgres psql -v ON_ERROR_STOP=1 -U aideepin -d aideepin < $MIG/all_dml_cn.sql
```

### 3.3 校验：check_init.sh

```bash
bash E:/reg-project/tmp-bge-verify/check_init.sh cn
bash E:/reg-project/tmp-bge-verify/check_init.sh en    # 英文包
bash E:/reg-project/tmp-bge-verify/check_init.sh cn --keep   # 失败时保留临时库便于排查
```

原理：在临时空库上重放 `all_ddl → all_dml → all_dml_<lang>`，然后与当前库做三层 diff：

| 层 | 比对内容 | 判据 |
|---|---|---|
| 结构层 | 表 / 列 / 索引 / 约束 / 触发器 / 函数 / 注释 / 序列 / 视图 | **`TOTAL DIFF LINES = 0` 才算 SQL 已同步** |
| 数据层 | 主数据 `name` 集合 + 全表行数 | dev 库有 diff 多为测试数据，**不用慌** |
| 值层 | 主数据字段值（`properties` / `is_enable` / `display_order` …） | 同上 |

> ⚠️ **红≠错**：结构层红说明你改了库却没同步 `all_*.sql`；
> 数据层红多半是运行时数据（mock 模型、测试用户、扫测组件），**不该进初始化种子**。

### 5.6 熔断与回收机制

| 机制 | 阈值 | 行为 |
|---|---|---|
| 心跳超时 | 5 分钟无进度回写 | 任务重置回 pending，重派给别的 Worker |
| 单任务时限 | 24 小时 | 强制失败 |
| `workerEpoch` 校验 | 每次回传 | 任务被重派后，旧 Worker 的迟到写入被拒（`accepted=false`），Worker 应立即退出 |
| `stopRequested` | 管理端点停止 | Worker 尽快中止并上报 `stopped` |

> Worker 侧的**心跳与进度回写是合一的**（`POST /job/{uuid}/progress`）；
> 训练报告随 `complete` 一起上报，落在 `adi_finetune_job.metrics`。

## 六、Docker Compose 全栈部署

### 6.1 服务编排

`aideepin/docker/docker-compose.yml` 编排 5 个服务：

| 服务 | 镜像 / 构建 | 暴露端口 | 说明 |
|---|---|---|---|
| `redis` | `redis:6.2.5` | 6379 | `--appendonly yes`，数据挂 `/data/redis/data` |
| `aideepin-api` | 多阶段构建 `server/Dockerfile` | 9999 | 后端，挂载 `/data/aideepin` 与 `/data/aideepin-logs` |
| `aideepin-user-web` | `user-web/Dockerfile` | —（内部） | 用户端静态站 |
| `aideepin-admin-web` | `admin-web/Dockerfile` | —（内部） | 管理端静态站 |
| `nginx` | `nginx:alpine` | **80** | 统一入口 |

> 注意：**PostgreSQL 不在编排里**，生产请用外部数据库或自行补足，并按第 3 节完成初始化。

### 6.2 Nginx 路由

| 路径 | 转发目标 |
|---|---|
| `/api/*` | → `aideepin-api:9999`（rewrite 去掉 `/api` 前缀） |
| `/admin/*` | → `aideepin-admin-web:80` |
| `/` | → `aideepin-user-web:80` |

> nginx.conf 用**变量式 `proxy_pass` + `resolver 127.0.0.11 valid=10s`**，
> 容器重建后能重新解析 IP，避免经典的 502。
> SSE 接口已配 `proxy_buffering off`。

## 七、验证：怎么确认部署成功

按顺序做这 6 项检查：

```bash
# 1) 容器都活着
docker ps --format "{{.Names}}\t{{.Status}}"
# 期望：adi-dev-postgres (healthy)、adi-dev-redis、aideepin-api

# 2) 端口在监听
netstat -ano | grep -E ":9999|:5432|:6379"
# 期望 9999 / 5432 / 6379 都是 LISTENING

# 3) 表数量对得上（期望约 51~60）
docker exec adi-dev-postgres psql -U aideepin -d aideepin -tAc \
  "select count(*) from information_schema.tables where table_schema='public';"

# 4) 工作流节点已注册（应含 Start/End/.../Mcp/Skill 共 20 个）
docker exec adi-dev-postgres psql -U aideepin -d aideepin -tAc \
  "select name from adi_workflow_component where display_order < 900 order by display_order;"

# 5) 健康检查接口
curl http://localhost:9999/swagger-ui.html

# 6) 初始化脚本与现库零差异（结构层）
bash E:/reg-project/tmp-bge-verify/check_init.sh cn
```

## 十、部署故障速查

| 现象 | 原因 / 排查 |
|---|---|
| 后端起不来，报 `Could not find or load main class` | 用了 Git Bash 的 `mvn`。改用 §2.1 的 `java -classpath plexus-classworlds` 写法 |
| 🔴 **后端启动报 `Port 55805 was already in use`**（或别的陌生端口） | 本机环境变量里有 **`SERVER__PORT`**（双下划线），Spring Boot 的 relaxed binding 把它当成了 `server.port`，把 9999 顶掉了。**启动时显式加 `--server.port=9999`**，或先 `unset SERVER__PORT`。详见 §2.1 末尾 |
| `Unsupported class file major version` | 用了 JDK8。必须 JDK17 |
| 后端起不来，提示 AES key 非法 | `ADI_ENCRYPT_AES_KEY` 不是 **16 位** |
| 启动日志 `WARN` 提到 ANN index / dimension | embedding 维度 > 2000（如 2048），HNSW 建不了。换 ≤2000 维模型，现用 1024 维 |
| 前端能开但接口全 401 | `Authorization` 头带了 `Bearer ` 前缀。**本项目要裸传 token** |
| 🔴 **直连 `:9999/api/auth/login` 返回 401 且响应体为空** | 路径错了。后端真实路径是 `/auth/login`，**没有 `/api` 前缀**（`/api` 是前端 Vite 代理的前缀，转发时会被 rewrite 掉）。`context-path` 为 `/` 时 `TokenFilter` 的 `contextPath + "/auth/"` 会拼成 `//auth/`，匹配不上 `/api/auth/login`，于是被直接拦掉。日志特征：`TokenFilter Unauthorized:/api/auth/login`。**调试请走 `:1003`，或用 `:9999/auth/login`** |
| 管理后台登录报「用户名或密码错误」 | 先看上面一行排除路径问题；再确认密码是否被测试脚本改过（比对 `adi_user.password` 与 `all_dml.sql` 的种子哈希）。重置方法见《系统操作手册》§0.4.1 |
| 登录页突然强制要求图形验证码 | 连续输错 **3 次**触发（`LOGIN_MAX_FAIL_TIMES=3`）。清 Redis：`docker exec adi-dev-redis redis-cli --scan --pattern "user:login:fail:*"` 后逐个 `del` |
| SSE 收不到流式内容 | Nginx 未配 `proxy_buffering off`；或前端用了 `EventSource`（应用 `fetch` + Reader） |
| 容器重建后访问 502 | Nginx 硬编码了容器 IP。确认用了变量式 `proxy_pass` + `resolver` |
| 上传文档后永远搜不到 | 一是白名单外类型被拒（看返回值与 `adi_document` 行数）；二是扫描件无文本层（开 OCR 或先看 FAIL 原因） |
| 知识库改了配置重启后失效 | **该字段没在 `KbInfoResp` 里读回**，管理端保存时把它覆盖成「关闭」了 |
| 前端某面板白屏/不渲染 | i18n 文案里写了字面花括号（生产模式抛 SyntaxError）。跑 `check-i18n-braces.mjs` |
| 批量上传卡死整个系统 | 连接池太小。设 `ADI_DB_POOL_SIZE=32` |
| 点「工作流节点」报 `unsupported workflow component` | `adi_workflow_component` 表里没注册该节点。执行对应迁移（如 023） |
| `check_init.sh` 数据层报 diff | 多半是 dev 测试数据，**结构层 DIFF=0 即为合格** |
| 训练任务一直 pending | Worker 没起来 / Worker Key 不对 / 心跳超时被回收。看 §5.6 |
