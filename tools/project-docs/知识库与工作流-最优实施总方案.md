## 零、这份方案和前两份的关系

前两份是**分册**（一份讲知识库、一份讲工作流），各自成立。本份做三件事：

1. **合并去重** —— 去掉重复项（如迁移编号、国际化铁律、构建门禁只写一次）
2. **重排顺序** —— ⚠️ **不是把两份拼起来**。两块有强耦合，且有一处排序错误需要纠正（见 §1.2）
3. **落到任务卡** —— 每项写明**改哪个文件、改什么、怎么验证**

## 一、为什么必须重排

### 1.1 两块的真实耦合点

| 耦合点 | 说明 |
|---|---|
| **工作流 KNOWLEDGE_RETRIEVER 节点是 ACL 的最大暴露面** | 节点由 Agent 发起检索，最容易被绕过主体权限。M1 的过滤规则必须覆盖它，否则等于留后门 |
| **工作流是 RAG 质量观测的最大数据源** | M4 的检索日志若只覆盖问答页，工作流调用会成盲区 |
| **M2/M3 检索 API 可直接被工作流 HTTP_REQUEST 节点调用** | 这是「知识库用到各业务」最快的一条路径——**零前端改动**，业务方自己在工作流里调 |
| **M6 记忆的工作流/Agent 复用** | 记忆挂在 userId 上，Agent 节点发起时才生效 |

### 1.2 ⚠️ 需要纠正的一处排序

**原知识库 PRD 的排期是「M1 ACL → M2 API → M3 MCP → M4 可观测」，这里要改。**

理由：M1 上线后如果出现过滤失效（**尤其是工作流节点绕过主体权限**），**没有 M4 的日志就无法定位是哪次请求、哪条过滤表达式出的问题**。而本项目既有的安全教训反复指向同一个模式——**先安全网后改动，顺序不可颠倒**。

**修正为：M4 的「检索日志」部分必须与 M1 同批或提前上线**（只取日志能力，看板可延后）。

### 1.3 最终排序（三线并行）

原两份是串行排的，实际可**三线并行**——因为三者的代码与文件基本不重叠：

| 线 | 内容 | 依赖 |
|---|---|---|
| **线 A · 安全与开放** | M4a 日志 → M1 ACL → M2 API → M3 MCP | 无（可立即开始） |
| **线 B · 体验止血** | W0 性能止血 → W1 视觉 → W2 交互 → W3 调试 | 无（可立即开始） |
| **线 C · 知识增强** | M5 知识包 → M6 记忆 | A 线完成 |

**建议：线 A 与线 B 同时启动**，两条线由不同人负责，互不阻塞。

## 三、线 A 实现要点（做什么 / 怎么做）

### 3.1 A-01 检索日志

**表**：`adi_rag_query_log`（迁移 `036_rag_query_log.sql` + 索引 `037`）

| 字段 | 说明 |
|---|---|
| `trace_id` | 链路追踪 |
| `user_id` / `api_key_uuid` | 主体；Agent 场景记 `agent_id` |
| `source` | `CHAT` / `KB_QA` / `WORKFLOW` / `AGENT` / `EXT_API` / `MCP` |
| `query_text` | ⚠️ **落库前脱敏 PII** |
| `kb_uuids` / `acl_filter_expr` | 授权库 + 实际过滤表达式 |
| `hit_segment_ids` / `neighbor_added` / `assert_failed` | 召回 / 扩窗 / 断言失败 |
| `embedding_ms` / `rerank_ms` / `llm_ms` / `token_count` | 耗时与成本 |
| `feedback` | `UP` / `DOWN` / 空 |

**四条硬约束**：
1. **异步写入，失败不影响主链路**（吞掉 + 计数告警）
2. **`query_text` 入库前脱敏**（手机号 / 身份证 / 邮箱）
3. **保留 ≤ 90 天 + 自动清理**（项目有「残留撑爆配额」事故）
4. **`source` 必须区分 WORKFLOW**——否则工作流调用成观测盲区

### 3.2 A-02 越权评测集

**这是 A 线的强制门禁**，构成：
- 30 条「用户无权但库中存在答案」的问题
- 每篇文档注入 **128 位 CSPRNG 哨兵令牌**
- 校验 4 个面：提示词、答案正文、引用列表、原始 JSON 响应体
- **通过标准：泄露率 = 0.00%**
- **反事实校验**：受限文档物理删除后，无权用户的响应必须**完全一致**（不得因文档存在与否泄露信息）

### 3.3 A-05 五条检索链路（一个都不能漏）

| 入口 | 位置 |
|---|---|
| 对话检索 | `CharacterChatHelper.retrieve()` |
| 知识库问答页 | `KnowledgeBaseService.sseAsk` / `blockingAsk` |
| 工作流 KNOWLEDGE_RETRIEVER 节点 | 节点实现 |
| Agent 工具检索 | Agent 工具链 |
| 开放 API | A-08 新增代码 |

**过滤表达式**

```
And( IsIn(KB_UUID, 授权库),
     Or( IsEqualTo(ACL_SENSITIVITY, "PUBLIC"),
         IsIn(ACL_VISIBILITY_GROUPS, 当前用户可见组) ) )
```

**四条硬约束**：
1. 过滤条件**必须来自请求主体**，严禁来自 query 或请求体
2. **双保险**：向量库过滤 + 取回后应用层断言，两道都过才进上下文
3. 断言失败的片段**直接丢弃 + 写审计 + warn 告警**，**不得「拿给模型参考一下」**
4. Agent/工作流发起时，可见组取**发起者用户上下文**，不得用 Agent 默认组

### 3.4 A-08 只检索 API

**端点**：`POST /ext/v1/knowledge/retrieve`

**请求**：`query`(必填)、`kbUuids[]`、`topK`(默认 5/上限 20)、`minScore`、`withNeighbor`、`responseMode`

**响应**：`contents[]`（含 `text` / `score` / `kbUuid` / `docUuid` / `docTitle` / `position` / `isNeighbor`）+ `skippedKbUuids[]` + `traceId`

**五条硬约束**：
1. **多库全局按 score 降序合并**，不按库分组
2. **无权库静默跳过**，但 `NOT_FOUND` 与 `NO_PERMISSION` 返回**一致响应**——不得通过响应差异泄露库是否存在
3. **每条必须带 `docUuid` + `position`**（可溯源）
4. **不调用 LLM**（`usage` 只含 embedding 侧）
5. **ACL 必须生效**，复用 A-05 同一套

### 3.5 ⚠️ A-10 与 A-08 的强约束

**MCP 的 `kb_search` 必须与 `/knowledge/retrieve` 复用同一检索内核。**

**禁止为 MCP 另写一套检索实现。** 否则必然出现「工作流里能搜到、MCP 里搜不到」的行为漂移，这是风险项 RK-06。代码评审时把这条列为**重点检查项**。

## 四、线 B 实现要点（做什么 / 怎么做）

### 4.1 B-01 补 `content_line` 样式（第一步，阻塞后续所有美化）

**现状**：12 个节点文件使用 `content_line`，**全项目无任何定义**，`global.less` 仅 10 行。

**后果**：只剩 Tailwind 的 `flex items-center` 生效 → 节点内容行无间距、无边框、无层级 → 渲染成挤在一起的裸文本。**这就是「页面太丑」的直接根因。**

**做法**：新增 `src/styles/workflow.less`，定义：

| 属性 | 值 |
|---|---|
| 行高 | 28px |
| **行间距** | **8px**（当前完全没有 = 挤成一团） |
| 标签列 | 固定 64px，`#6B7280`，12px |
| 值列 | `#111827`，13px，超出 ellipsis，hover 显示完整值 |

同时定义 `.wf-node-card`（280px 宽、8px 圆角、`0 1px 3px rgba(0,0,0,.08)`、hover 提升、选中 2px `#3B82F6` + 外发光）。

⚠️ 节点卡片宽度**当前由内容自适应**，导致同类节点宽度参差 → 统一 280px，长内容内部滚动。

| **连线数据流** | 执行路径上出现流动粒子（ComfyUI 做法），用户不用点日志就知道走了哪条路 |
| 节点状态 chip | hover 显示耗时/token/输入输出摘要。⚠️ **默认隐藏按需展开**，不在画布堆满数字 |
| 单节点重跑 | 只重跑选中节点及其上游（对应既有 `retryIndex?force=true` 重嵌入口） |

⚠️ **项目铁律**：前端加节点是**「六处注册」不是五处**——`nodes/index.ts` → `WorkflowDefine.vue` slot → `WfDefineRightPanel.vue` 属性面板 → `workflow-util.ts` 默认值/图标 → locales 中英文案 + `componentTitle` → **`RuntimeNodes.vue` 按 `metadata.type` 渲染指标 chip**。

漏第六处 = **指标写库但界面不显示**。B-15~B-20 新增节点能力时必须同步第六处。

## 五、执行顺序与并行策略

```
第 1 周 ────────────────────────────────────────
  线 A（安全）      A-01 日志 → A-02 越权评测集 ← 必须先于 A-03
  线 B（体验）      B-01 补样式 → B-02 性能止血
                    └ 两条线代码/文件不重叠，可并行

第 2–3 周 ──────────────────────────────────────
  线 A              A-03 迁移 → A-04 固化 → A-05 过滤 → A-06 回填
  线 B              B-03 节点卡片 → B-04 画布 → B-05 属性面板 → B-06 四态

第 4–5 周 ──────────────────────────────────────
  线 A              A-07 管理端 → A-08 API → A-09 限流 → A-10 MCP
  线 B              B-07 撤销 → B-08~B-13 交互集

第 6–7 周 ──────────────────────────────────────
  线 A              上线 + 72 小时验证
  线 B              B-14 运行态
  线 C              C-01 看板 → C-02 闭环 → C-03/04 知识包 → C-05 记忆

第 8 周+ ───────────────────────────────────────
  B-15~B-20 节点能力增强
  X-01~X-06 单独立项
```

**关键节点门禁**：

| 门禁 | 条件 | 不满足 |
|---|---|---|
| G1 | A-02 越权评测集建成并可复跑 | **不得开始 A-03** |
| G2 | A-05 越权泄露率 = 0.00%，且**有权问题仍能正常召回** | 不得进入 A-07 |
| G3 | B-01 完成且节点间距/层级生效 | B-03~B-04 美化不得开工 |
| G4 | B-02 有改造前后对比数据 | 不得提交评审 |
| G5 | A-10 有**真实 MCP 客户端截图** | 不得上线 |
| G6 | 存量行为回归全绿（ACL 改造后检索结果与上线前一致） | 不得上线 |

⚠️ **G2 特别强调**：越权评测通过**不得**以牺牲正常功能为代价。**有权问题召回率下降同样算失败**——历史上出现过「僵尸 SQL 撑绿」的假通过。
